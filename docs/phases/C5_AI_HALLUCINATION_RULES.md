# C5 AI HALLUCINATION RULES, DETERMINISTIC NUMBER GOVERNANCE & UNKNOWN HANDLING

## Purpose
The **AI Hallucination Rules, Deterministic Number Governance & Unknown Handling Tier** provides hard server-side guardrails, real-time response scrubbing, anti-fabrication interceptors, and standardized unknown handling protocols for all AI interactions across the ASCANALYST platform.

In clinical, surgical, and financial healthcare operations, generative AI hallucinations—such as inventing unbilled revenue, guessing payer contract allowable rates, hallucinating non-existent CPT codes, or fabricating physician productivity metrics—introduce catastrophic compliance, audit, and operational liabilities. Phase C5 establishes that:
1. **Zero Generative Arithmetic**: Generative LLM token sampling is strictly prohibited from performing mathematical additions, multiplications, variances, percentages, or margins. All calculations are executed exclusively by server-authoritative deterministic routines (Phase C1, C3, and C4) and injected into responses as immutable, verified values.
2. **Real-Time Number Scrubber & Anti-Fabrication Interceptor**: Every candidate response generated by the AI Analyst undergoes strict server-side AST and regular expression tokenization. Any numerical claim (currency `$X`, percentage `X%`, time intervals, procedure volumes) that lacks an exact match in the underlying Phase C4 evidence citations or authoritative tool payload triggers an immediate `FABRICATION_INTERCEPTED` block.
3. **Formal Unknown Handling Protocol ("I Do Not Know")**: When data is unrecorded, out of scope, or missing from the facility database, the AI must never speculate, guess, or extrapolate. Instead, it must follow a formal, structured response protocol stating data unavailability, identifying missing prerequisites, and recommending valid alternative queries.
4. **Authoritative Code & Entity Validation**: All procedure codes (CPT/HCPCS), billing modifiers, CARC/RARC codes, and national provider identifiers (NPI) referenced in AI narratives must be validated against licensed AMA CPT manuals and facility master directories.

## Target State
1. **The Number Scrubber Lifecycle**:
   - Step 1 (Input Generation): LLM generates candidate text narrative.
   - Step 2 (Token Extraction): Scrubber extracts all currencies (`\$[\d,]+(\.\d{2})?`), percentages (`\d+(\.\d+)?%`), integers, and floats.
   - Step 3 (Ground-Truth Matching): Each number is reconciled against:
     - Output fields of executed tools in the active session.
     - Claimed values in attached Phase C4 citations.
   - Step 4 (Decision Gate):
     - If all numbers match ground truth within 0.1% tolerance: Response is signed with SHA-256 validation seal and dispatched (`PASSED`).
     - If ungrounded numbers are detected: The response is blocked, logged to `ai_hallucination_intercept_logs`, and replaced with a verified fallback or structured unknown refusal (`INTERCEPTED`).
2. **Structured Unknown Refusal Template**:
   - Responses addressing unrecorded parameters must adhere to canonical template:
     ```json
     {
       "status": "UNKNOWN_DATA",
       "reason": "NO_MATCHING_RECORDS",
       "explanation": "No authoritative surgical records found for Dr. Vance on CPT 27447 in Naples Surgery Center for Q3 2026.",
       "missingPrerequisites": ["Electronic Case Master entry in 'cases' table", "Completed anesthesia record"],
       "recommendedAction": "Query 'cpt_economics_query' to view facility-wide knee arthroplasty benchmarks."
     }
     ```
3. **Prohibited Hallucination Patterns (Hard Bans)**:
   - Inventing dollar amounts or variances not present in the billing ledger.
   - Guessing procedure durations without citing historical OR sensor logs.
   - Extrapolating staffing costs without facility wage parameters.
   - Fabricating regulatory CMS payment policies or ambulatory surgical center list inclusion status.

-- 1. AI Hallucination Guardrail Policies
CREATE TABLE IF NOT EXISTS public.ai_hallucination_guardrails (
    id VARCHAR(64) PRIMARY KEY, -- e.g. 'RULE-DETERMINISTIC-MATH', 'RULE-NUMBER-SCRUBBER'
    name VARCHAR(128) NOT NULL,
    category VARCHAR(32) NOT NULL, -- 'ARITHMETIC', 'EVIDENCE_GROUNDING', 'UNKNOWN_HANDLING', 'TERMINOLOGY', 'SAFETY'
    description TEXT NOT NULL,
    severity VARCHAR(16) NOT NULL DEFAULT 'BLOCK', -- 'BLOCK', 'WARN', 'REDACT'
    detection_pattern TEXT, -- Regex or AST rule identifier
    confidence_threshold NUMERIC(5,2) NOT NULL DEFAULT 95.00,
    is_active BOOLEAN NOT NULL DEFAULT true,
    created_at TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    updated_at TIMESTAMPTZ NOT NULL DEFAULT NOW()
);

-- 2. AI Hallucination Intercept Audit Log
CREATE TABLE IF NOT EXISTS public.ai_hallucination_intercept_logs (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    facility_id UUID NOT NULL REFERENCES public.facilities(id) ON DELETE CASCADE,
    session_id VARCHAR(64) NOT NULL,
    rule_id VARCHAR(64) NOT NULL REFERENCES public.ai_hallucination_guardrails(id),
    intercept_type VARCHAR(32) NOT NULL, -- 'UNGROUNDED_NUMBER', 'FABRICATED_CODE', 'ARITHMETIC_DRIFT', 'UNVERIFIED_ASSERTION'
    raw_prompt TEXT NOT NULL,
    candidate_response TEXT NOT NULL,
    flagged_tokens JSONB NOT NULL DEFAULT '[]'::jsonb, -- Array of [{ token, expectedGroundTruth, reason }]
    action_taken VARCHAR(32) NOT NULL DEFAULT 'BLOCKED_AND_LOGGED', -- 'BLOCKED_AND_LOGGED', 'REPLACED_WITH_UNKNOWN', 'REDACTED'
    sanitized_response TEXT,
    provenance_hash VARCHAR(64) NOT NULL,
    created_at TIMESTAMPTZ NOT NULL DEFAULT NOW()
);

-- 3. AI Unknown Handling Templates
CREATE TABLE IF NOT EXISTS public.ai_unknown_handling_templates (
    id VARCHAR(64) PRIMARY KEY, -- e.g. 'UNKNOWN-MISSING-CASE', 'UNKNOWN-UNCONTRACTED-PAYER'
    category VARCHAR(32) NOT NULL,
    title VARCHAR(128) NOT NULL,
    standard_message TEXT NOT NULL,
    suggested_alternatives JSONB NOT NULL DEFAULT '[]'::jsonb,
    is_active BOOLEAN NOT NULL DEFAULT true,
    created_at TIMESTAMPTZ NOT NULL DEFAULT NOW()
);

-- Indexes
CREATE INDEX IF NOT EXISTS idx_ai_guardrails_active ON public.ai_hallucination_guardrails(is_active);
CREATE INDEX IF NOT EXISTS idx_ai_intercepts_facility ON public.ai_hallucination_intercept_logs(facility_id);
CREATE INDEX IF NOT EXISTS idx_ai_intercepts_rule ON public.ai_hallucination_intercept_logs(rule_id);
CREATE INDEX IF NOT EXISTS idx_ai_intercepts_type ON public.ai_hallucination_intercept_logs(intercept_type);

-- Views
CREATE OR REPLACE VIEW public.vw_ai_hallucination_intercept_metrics AS
SELECT 
    facility_id,
    COUNT(*) AS total_intercepts,
    COUNT(*) FILTER (WHERE intercept_type = 'UNGROUNDED_NUMBER') AS ungrounded_number_count,
    COUNT(*) FILTER (WHERE intercept_type = 'FABRICATED_CODE') AS fabricated_code_count,
    COUNT(*) FILTER (WHERE intercept_type = 'ARITHMETIC_DRIFT') AS arithmetic_drift_count,
    COUNT(*) FILTER (WHERE action_taken = 'BLOCKED_AND_LOGGED') AS blocked_count,
    MAX(created_at) AS latest_intercept_at
FROM public.ai_hallucination_intercept_logs
GROUP BY facility_id;

## Business Rules & Deterministic Verification
1. **Deterministic Number Scrubber Protocol**:
   - Every candidate response is scanned for numerical tokens using strict regular expressions:
     - Currencies: `\$[0-9]{1,3}(,[0-9]{3})*(\.[0-9]{2})?`
     - Percentages: `[0-9]+(\.[0-9]+)?%`
     - Numerics: `\b[0-9]+(\.[0-9]+)?\b`
   - Each identified token must exist in the active session's Ground Truth Context Pool (derived from Phase C3 tool results and Phase C4 citations).
   - If an ungrounded number is found, the response is blocked with status `FABRICATION_INTERCEPTED`.
2. **AMA CPT Manual Validation**:
   - 5-digit numerical codes matching CPT syntax (e.g. `29881`, `66984`) must be validated against `cpt_codes` master table.
   - Non-existent numbers (e.g. `99999`, `00000`, or invalid 5-digit strings) trigger immediate `FABRICATED_CODE` interception.
3. **Structured Unknown Fallback**:
   - When a requested data point yields 0 records, the AI Analyst must never extrapolate. It must respond with:
     > *"Authoritative records for [Entity] are unavailable in the facility database. [Prerequisite Requirements]. You may run [Suggested Tool Query] to review active records."*

- **Role-Based Inspection Controls**:
  - `facility_admin`, `super_admin`: Full access to configure guardrails, adjust confidence thresholds, and inspect unredacted raw candidate responses in intercept logs.
  - `compliance_officer`, `clinical_director`: Read access to hallucination intercept metrics, audit logs, and scrubber health telemetry.
  - `staff_user`, `read_only_analyst`: Beneficiaries of clean, scrubbed AI responses; cannot edit guardrail policies.
- **Audit Logging**: Every intercepted hallucination is logged with `facility_id`, `rule_id`, `flagged_tokens`, `raw_prompt`, and cryptographic SHA-256 provenance hash.
