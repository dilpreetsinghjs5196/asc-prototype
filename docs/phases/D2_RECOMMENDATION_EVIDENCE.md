# D2 RECOMMENDATION EVIDENCE

## Purpose
The Recommendation Evidence model establishes an immutable, auditable, and deterministic provenance chain linking every financial recommendation and Next Best Financial Action (NBFA) to its underlying authoritative clinical and financial source records. This ensures that no recommendation operates as an unverified "black box" and equips business office directors, revenue cycle specialists, and clinical administrators with immediate, legally defensible citations to source claims, 835 Electronic Remittance Advice (ERA) lines, payer contract clauses, and operative reports.

## Scope
- Define production-grade evidence data models linking `next_best_financial_actions` to source encounters, claims, remittances, contracts, and operative notes.
- Preserve full backward compatibility with ASCANALYST claim analysis pipelines, contract modeling, and surgical case scheduling.
- Implement deterministic Evidence Completeness Index (ECI) calculations and confidence tier evaluations.
- Enforce strict organization/facility tenancy isolation and granular Role-Based Access Control (RBAC).
- Redact Safe Harbor 18-identifier Protected Health Information (PHI) within evidence citation snippets while preserving exact cryptographic hashes for authoritative legal auditability.

## Current State
Prior to Phase D2, recommendations generated by the NBFA engine (`next_best_financial_actions`) and prioritized by the priority model (`recommendation_scoring_profiles`) contained scalar summary fields (`expected_financial_value`, `primary_reason_code`, `urgency_score`), but lacked granular relational linkages to specific 835 ERA adjustment line items, exact payer contract clauses, and clinical chart note excerpts.

## Target State
In the target state, every Next Best Financial Action is backed by a rich evidentiary graph:
1. **Multi-Source Linkage:** Each action references one or more typed evidence items (`CLAIM_LINE`, `REMITTANCE_CARC`, `PAYER_CONTRACT_CLAUSE`, `CLINICAL_OPERATIVE_NOTE`, `FEE_SCHEDULE_RULE`, `BENCHMARK_VARIANCE`).
2. **Deterministic Evidence Completeness Index ($ECI$):** A normalized score ($0.0 - 100.0\%$) reflecting whether the required evidentiary dimensions (claim discrepancy, remittance code, contractual clause, operative note) have been attached and verified.
3. **Cryptographic Provenance:** Every evidence item computes an authoritative SHA-256 hash across its source record ID, payload contents, and citation text, guaranteeing zero silent tampering.
4. **Verification & Dispute Lifecycle:** Revenue cycle managers can explicitly verify, contest, or supersede evidence items with required rationale logging.
5. **Interactive UI Verification:** The web interface presents an Evidence Explorer with side-by-side claim line comparisons, contract clause highlights, and redacted operative report excerpts.

## Data Model / Schema

### 1. `public.recommendation_evidence_items`
```sql
CREATE TABLE IF NOT EXISTS public.recommendation_evidence_items (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    action_id UUID NOT NULL REFERENCES public.next_best_financial_actions(id) ON DELETE CASCADE,
    facility_id UUID NOT NULL REFERENCES public.facilities(id) ON DELETE CASCADE,
    evidence_type VARCHAR(32) NOT NULL CHECK (evidence_type IN (
        'CLAIM_LINE',
        'REMITTANCE_CARC',
        'PAYER_CONTRACT_CLAUSE',
        'CLINICAL_OPERATIVE_NOTE',
        'FEE_SCHEDULE_RULE',
        'BENCHMARK_VARIANCE'
    )),
    source_table VARCHAR(64) NOT NULL,
    source_record_id VARCHAR(64) NOT NULL,
    title VARCHAR(160) NOT NULL,
    citation_snippet TEXT NOT NULL,
    evidence_payload JSONB NOT NULL DEFAULT '{}'::jsonb,
    confidence_tier VARCHAR(32) NOT NULL DEFAULT 'TIER_1_CONTRACTUAL' CHECK (confidence_tier IN (
        'TIER_1_CONTRACTUAL',
        'TIER_2_REMITTANCE_PRIMARY',
        'TIER_3_CLINICAL_DOCUMENTATION',
        'TIER_4_EMPIRICAL_BENCHMARK'
    )),
    confidence_score NUMERIC(5, 2) NOT NULL DEFAULT 95.00 CHECK (confidence_score >= 0.00 AND confidence_score <= 100.00),
    verification_status VARCHAR(24) NOT NULL DEFAULT 'VERIFIED' CHECK (verification_status IN (
        'VERIFIED',
        'PENDING_REVIEW',
        'CONTESTED',
        'SUPERSEDED'
    )),
    verified_by_user_id VARCHAR(64),
    verified_at TIMESTAMPTZ,
    cryptographic_evidence_hash VARCHAR(64) NOT NULL,
    created_at TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    updated_at TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    CONSTRAINT uq_action_source_evidence UNIQUE(action_id, evidence_type, source_record_id)
);

CREATE INDEX IF NOT EXISTS idx_rec_evidence_action ON public.recommendation_evidence_items(action_id);
CREATE INDEX IF NOT EXISTS idx_rec_evidence_facility ON public.recommendation_evidence_items(facility_id, verification_status);
CREATE INDEX IF NOT EXISTS idx_rec_evidence_type ON public.recommendation_evidence_items(evidence_type);
```


### 3. `public.vw_recommendation_evidence_summary`
```sql
CREATE OR REPLACE VIEW public.vw_recommendation_evidence_summary AS
SELECT
    a.id AS action_id,
    a.facility_id,
    a.action_code,
    a.category,
    a.expected_financial_value,
    COUNT(e.id) AS total_evidence_items,
    COUNT(e.id) FILTER (WHERE e.verification_status = 'VERIFIED') AS verified_evidence_items,
    COUNT(e.id) FILTER (WHERE e.verification_status = 'CONTESTED') AS contested_evidence_items,
    COUNT(e.id) FILTER (WHERE e.evidence_type = 'CLAIM_LINE') AS claim_line_citations_count,
    COUNT(e.id) FILTER (WHERE e.evidence_type = 'PAYER_CONTRACT_CLAUSE') AS contract_clause_citations_count,
    COUNT(e.id) FILTER (WHERE e.evidence_type = 'REMITTANCE_CARC') AS remittance_carc_citations_count,
    COUNT(e.id) FILTER (WHERE e.evidence_type = 'CLINICAL_OPERATIVE_NOTE') AS clinical_note_citations_count,
    COALESCE(ROUND(AVG(e.confidence_score), 1), 0.0) AS avg_evidence_confidence,
    MAX(e.updated_at) AS latest_evidence_updated_at
FROM public.next_best_financial_actions a
LEFT JOIN public.recommendation_evidence_items e ON a.id = e.action_id
GROUP BY a.id, a.facility_id, a.action_code, a.category, a.expected_financial_value;
```

## Business Rules

### 1. Deterministic Evidence Completeness Index ($ECI$)
The evidentiary readiness of an action is mathematically evaluated on a scale of $0.0\%$ to $100.0\%$:
$$ECI = \min\left(100.0, W_{\text{claim}} \cdot I_{\text{claim}} + W_{\text{remit}} \cdot I_{\text{remit}} + W_{\text{contract}} \cdot I_{\text{contract}} + W_{\text{clinical}} \cdot I_{\text{clinical}}\right)$$

Where the standard baseline weights are:
- $W_{\text{claim}} = 35.0\%$ (Specific claim lines, procedure codes, billed/allowed/paid metrics present)
- $W_{\text{remit}} = 25.0\%$ (835 ERA adjustment remark codes or payer denial reasons present)
- $W_{\text{contract}} = 25.0\%$ (Payer contractual clause, fee schedule section, or carve-out rate cited)
- $W_{\text{clinical}} = 15.0\%$ (Operative record excerpt, physician dictation, or clinical necessity note cited)

An action with all four primary evidence dimensions attached achieves an $ECI = 100.0\%$. Actions with $ECI < 60.0\%$ display an amber warning badge indicator prompting clinical/billing documentation review prior to execution.

### 2. Evidence Confidence Tiers
- **TIER_1_CONTRACTUAL (95-100%):** Legally binding executed payer contracts, CMS national statutory fee schedules, signed implant carve-out addenda.
- **TIER_2_REMITTANCE_PRIMARY (85-94%):** Direct clearinghouse EDI 835 Remittance Advice or EDI 837 claim transaction payloads.
- **TIER_3_CLINICAL_DOCUMENTATION (75-84%):** Signed operative notes, implant logs, and pathology reports.
- **TIER_4_EMPIRICAL_BENCHMARK (60-74%):** Historical facility peer median recoveries and empirical variance models.

### 3. Verification State Machine
- `VERIFIED`: Default state for automated system extractions meeting cryptographic check and minimum confidence criteria ($\ge 85\%$).
- `PENDING_REVIEW`: Flagged when confidence falls below $85\%$ or an amendment is detected in the source contract.
- `CONTESTED`: Marked by staff if the cited contract clause is disputed by the payer or superseded by a newer amendment.
- `SUPERSEDED`: Inactive status when replaced by a newer version of evidence.

### 4. Prohibited Behaviors
- **Zero Mock Citations:** Fabricated contract clause numbers (e.g., "Clause XYZ") or dummy claim lines are strictly prohibited.
- **Zero Raw PHI in Plaintext Snippets:** All citations presented in evidence payloads must have patient names, SSNs, and phone numbers masked in accordance with HIPAA Safe Harbor regulations.

## Permissions / Security
- **Tenancy:** Every evidence item and audit row is tied to `facility_id UUID`. All queries strictly enforce facility boundaries.
- **Role Permissions:**
  - `admin`, `financial_controller`: Full view, verify, contest, supersede, and export evidence packages.
  - `biller`, `auditor`: View evidence items, add review notes, and submit dispute flags.
  - `clinical_staff`: View clinical operative notes and procedure unbundling evidence only.
  - `viewer`: Read-only view with PHI permanently redacted.

## API / Service Requirements

### Backend Services (`recommendationEvidenceService.js`)
- `getEvidenceForAction(actionId, facilityId)`: Retrieves all evidence items for a given action with parsed payload details.
- `calculateEvidenceCompleteness(evidenceItems)`: Computes the deterministic $ECI$ ($0-100\%$).
- `verifyEvidenceItem(evidenceId, userId, userContext)`: Transitions status to `VERIFIED` and logs an audit record.
- `contestEvidenceItem(evidenceId, rationale, userId, userContext)`: Transitions status to `CONTESTED` with mandatory justification.
- `getEvidenceTelemetry(facilityId)`: Computes facility-wide evidence metrics (total citations, verification rate, average $ECI$).
- `computeEvidenceHash(evidenceObject)`: Generates authoritative SHA-256 hash for cryptographic provenance.

## UI / Workflow Requirements
- **Evidence Explorer Drawer & Matrix:**
  - **Telemetry Ribbon (5 Cards):** Total Evidence Citations, Verified Contractual Rate %, Claim-Line Traceability %, Average Evidence Completeness ($ECI$), Uncontested Integrity %.
  - **Action Selection Table:** Displays actions with priority rank, category, expected value, and Evidence Completeness Badge.
  - **Evidence Detail Panel:**
    - **Source Case & Claim Card:** Case ID, DOS, Surgeon, CPT codes, Billed vs Paid discrepancy table.
    - **Remittance (835 ERA) Discrepancy Card:** Adjustment codes (CARC 97, RARC N390), adjudicated amounts, denial explanations.
    - **Contractual & Fee Schedule Citation Card:** Exact contract clause, carve-out terms, rate calculations, effective date validity.
    - **Clinical Operative Documentation Card:** Operative report snippet with highlighted surgical technique justifying separate reimbursement.
    - **Cryptographic Provenance Footer:** SHA-256 hash, calculation timestamp, and verification audit ledger.
- **Interactive Modals:**
  - **Contest Evidence Modal:** Requires entering a business rationale before flagging evidence as contested.
  - **Export Evidence Dossier:** Generates an auditable appeal packet with verified citations.

## Audit / Provenance
Every evidence record maintains:
- `cryptographic_evidence_hash`: Authoritative SHA-256 digest computed from `action_id`, `evidence_type`, `source_record_id`, `evidence_payload`, and `citation_snippet`.
- `recommendation_evidence_audits`: Immutable ledger tracking every transition, timestamp, user identity, previous status, and rationale.
